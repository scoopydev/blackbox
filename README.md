# BLACKBOX

A 2D puzzle game about signals and circuits, built in Unity.

## Concept

Every puzzle is a circuit you don't understand yet. You're given a set of **inputs** and the **outputs** the circuit is supposed to produce. Between them sits a network of components, and **you don't know what any of them do**.

The core loop is experimentation:

1. **Probe** – change a component, flip an input, rewire a connection.
2. **Observe** – watch how the signals and outputs change.
3. **Deduce** – form a theory about each component's hidden rule.
4. **Solve** – use what you've learned to make the circuit's outputs match the target.

There is no tutorial text explaining the parts. Understanding *is* the puzzle.

## Design pillars

- **Learn by doing.** Every rule is discoverable through play; nothing is told to the player.
- **Readable signals.** Signal state should always be visible, so cause and effect is clear.
- **Fair mysteries.** Each component behaves consistently, so careful observation always pays off.
- **Rules carry over.** Knowledge from earlier puzzles builds toward later, more complex circuits.

## Project layout

```
Assets/
  _Project/            All game-specific content lives here
    Scripts/
      Core/            Game state, level loading, shared utilities
      Circuit/         Signal model, wires, graph evaluation / simulation
      Components/      Individual circuit component behaviours (the "black boxes")
      Puzzles/         Puzzle definitions, win-condition checks
      UI/              HUD, menus, input/output panels
      Editor/          Custom inspectors and level-authoring tools
    Prefabs/
      Components/      Prefabs for each circuit component
      UI/
    Scenes/
    Puzzles/           Puzzle data (ScriptableObjects)
    Art/               Sprites, UI art
    Audio/             SFX and music
    Materials/
    Fonts/
Packages/              Unity package manifest (generated by Unity)
ProjectSettings/       Unity project settings (generated by Unity)
Docs/                  Design notes
```

Third-party assets from the Asset Store go outside `_Project` so they stay separate from our own code and content.

## Getting started

### Requirements

- Unity 6 (6000.x LTS) with the 2D template
- [Git LFS](https://git-lfs.com/) – binary assets (images, audio, fonts) are stored in LFS

### First-time setup

```bash
git lfs install
git clone https://github.com/scoopydev/blackbox.git
```

Then in Unity Hub: **New project → 2D (URP) template**, and set the location to the cloned `blackbox` folder (or create the project elsewhere and move `Assets/`, `Packages/` and `ProjectSettings/` into the repo). Commit the generated `Packages/` and `ProjectSettings/` folders.

### Recommended Unity settings

These are on by default in recent Unity versions, but check them under **Edit → Project Settings → Editor**:

- **Version Control → Mode:** Visible Meta Files
- **Asset Serialization → Mode:** Force Text

### Smart Merge (optional)

To merge scenes and prefabs more cleanly, add Unity's YAML merge tool to your git config:

```ini
[merge "unityyamlmerge"]
    name = Unity SmartMerge
    driver = '<path to Unity>/Editor/Data/Tools/UnityYAMLMerge' merge -p %O %B %A %A
    recursive = binary
```
